## 1. spec_helper に INTERNAL_API_KEY のテスト用デフォルト値を設定する

**指摘**: `idp-client/spec/spec_helper.rb`
テスト実行時に `INTERNAL_API_KEY` が未設定だと、request spec 内の `ENV.fetch('INTERNAL_API_KEY')` が `KeyError` になって失敗する。CI/ローカル実行を安定させるため、テスト用のデフォルト値を設定する。

**対処法**: `spec_helper.rb` の先頭（`require_relative '../config/environment'` より前）でデフォルト値を設定する。

```ruby
ENV['RAILS_ENV'] ||= 'test'
ENV['INTERNAL_API_KEY'] ||= 'test_internal_api_key'
require_relative '../config/environment'
```

## 2. 内部APIキー認証の KeyError 回避と secure_compare 化

**指摘**: `idp-client/app/controllers/application_controller.rb`
`ENV.fetch('INTERNAL_API_KEY')` は未設定時に `KeyError` で 500 になる（設定漏れ時に挙動が不明瞭）。また、APIキー比較は `secure_compare` を使うとタイミング攻撃を避けられる。

**対処法**: キー未設定時は即 401 を返し、比較は `ActiveSupport::SecurityUtils.secure_compare` を使う。なお `secure_compare` は長さが異なると `ArgumentError` を投げるため、固定長ダイジェスト同士で比較するのが安全。

```ruby
def require_internal_api_key
  expected = ENV['INTERNAL_API_KEY']
  provided = request.headers['X-Internal-API-Key']

  if expected.blank? || provided.blank?
    return render json: { error: 'Unauthorized' }, status: :unauthorized
  end

  valid = ActiveSupport::SecurityUtils.secure_compare(
    Digest::SHA256.hexdigest(provided),
    Digest::SHA256.hexdigest(expected)
  )
  render json: { error: 'Unauthorized' }, status: :unauthorized unless valid
end
```

## 3. Clients API の create / index にも認証を必須化する

**指摘**: `idp-client/app/controllers/api/v1/clients_controller.rb`
Clients API は `client_secret` の払い出し・一覧返却を行うため、認証なし公開は重大な情報露出・不正発行につながる。現状 `before_action :require_internal_api_key, only: :show` のみ。VerifyController と同様に create / index / show すべてを内部APIキー必須に揃える。

**対処法**: `only` 指定を外して全アクションに適用する。

```ruby
before_action :require_internal_api_key
```

あわせて対応する request spec（`spec/requests/clients_spec.rb`）の全リクエストにヘッダーを付与するよう更新する。

```ruby
let(:headers) { { 'X-Internal-API-Key' => ENV.fetch('INTERNAL_API_KEY') } }

post '/api/v1/clients', params: valid_params, headers: headers
```

## 4. Client モデルに require 'uri' を明示する

**指摘**: `idp-client/app/models/client.rb`
`redirect_uris` のバリデーションで `URI.parse` を使っているが、リポジトリ内に `require 'uri'` が見当たらない（48 行目も同様）。環境によっては `URI` 定数が未ロードで `NameError` になる。

**対処法**: ファイル先頭で明示的に require する。

```ruby
require 'bcrypt'
require 'uri'

class Client < ApplicationRecord
```

## 5. テスト環境では BCrypt のコストを MIN_COST に下げる

**指摘**: `idp-client/app/models/client.rb`
`client_secret=` が常に BCrypt のデフォルトコストでハッシュ化するため、FactoryBot などでテストが大量に Client を作るとテストスイートが極端に遅くなる。

**対処法**: test 環境では `BCrypt::Engine::MIN_COST` を使う。

```ruby
def client_secret=(value)
  return if value.blank?

  @client_secret = value
  cost = Rails.env.test? ? BCrypt::Engine::MIN_COST : BCrypt::Engine.cost
  self.client_secret_hash = BCrypt::Password.create(value, cost: cost)
end
```

## 6. requests/clients_spec の bcrypt 接頭辞チェックを実検証に変える

**指摘**: `idp-client/spec/requests/clients_spec.rb`
bcrypt のハッシュ接頭辞は環境・バージョンで `$2a$` 以外（例: `$2b$`）になることがあり、`start_with('$2a$')` のテストは不必要に脆い。生成された平文 `client_secret` が実際に検証できることを確認する形にすると堅牢。

**対処法**: レスポンスの平文シークレットで `client_secret_valid?` が通ることを検証する。

```ruby
it '発行した平文 client_secret が検証できる' do
  post '/api/v1/clients', params: valid_params, headers: headers
  client = Client.order(:created_at).last
  expect(client.client_secret_valid?(response.parsed_body['client_secret'])).to be true
end
```

## 7. models/client_spec の bcrypt 接頭辞チェックを緩める

**指摘**: `idp-client/spec/models/client_spec.rb`
同様に `$2a$` 固定の前提は環境・バージョン差で崩れる可能性がある。ここでは既に `client_secret_valid?` を検証しているので、接頭辞チェックは `present` 程度に留めるか削除する。

**対処法**:

```ruby
expect(client.client_secret_hash).to be_present
expect(client.client_secret_valid?('raw_secret')).to be true
```

## 8. demo-rp の VITE_CLIENT_SECRET を seeds.rb と一致させる

**指摘**: `demo-rp/.env.example`
`.env.example` の `VITE_CLIENT_SECRET=demo_client_secret` が、`idp-client/db/seeds.rb` で作成しているデモクライアントの平文シークレット（`demo_secret`）と一致しておらず、このままではデモRPが認証に失敗する。

**対処法**: `demo-rp/.env.example` を seeds.rb に合わせる。

```dotenv
VITE_CLIENT_SECRET=demo_secret
```

## 補足. redirect_uris の host 存在チェック（低信頼度コメント）

**指摘**: `idp-client/app/models/client.rb:51`（低信頼度のため抑制済み）
URL判定が `URI::HTTP` / `URI::HTTPS` かどうかだけなので、`http://` のように host が無い不正なURLでも通る可能性がある。

**対処法**: host の存在もチェック対象に加える。

```ruby
parsed = URI.parse(uri)
valid = (parsed.is_a?(URI::HTTP) || parsed.is_a?(URI::HTTPS)) && parsed.host.present?
errors.add(:redirect_uris, "#{uri} is not a valid URL") unless valid
```
