# SSOシステム要件定義書

## 1. プロジェクト概要

### 1.1 目的
本プロジェクトでは、OAuth 2.0 / OpenID Connect (OIDC) プロトコルに準拠したシングルサインオン（SSO）認証基盤を自作し、そのプロトコル仕様とセキュリティ要件の理解を深めることを目的とする。

### 1.2 スコープ
- SSOのIdP（Identity Provider）機能の実装
- クライアントアプリケーション（RP: Relying Party）の登録・管理
- エンドユーザーの認証・セッション管理
- アクセストークン・IDトークンの発行と検証

### 1.3 対象外（今後の拡張）
- SAMLプロトコル対応
- 多要素認証（MFA）
- ソーシャルログイン連携（外部IdP）
- 本番環境における高可用性構成（クラスタリング等）

---

## 2. 用語定義

| 用語 | 説明 |
|---|---|
| IdP | Identity Provider。本システム自身。 |
| RP | Relying Party。本SSOを利用するクライアントアプリケーション。 |
| Access Token | 保護リソースへのアクセスに使用するトークン。 |
| ID Token | ユーザーの認証情報を含むJWT。 |
| Authorization Code | アクセストークンと交換するための一時コード。 |

---

## 3. 機能要件

### 3.1 認証フロー（OIDC）
- **Authorization Code Flow** をサポートする。
- 以下のエンドポイントを提供する：
  - `GET /.well-known/openid-configuration` (Discovery)
  - `GET /authorize` (認証・同意)
  - `POST /token` (トークン発行)
  - `GET /userinfo` (ユーザー情報取得)
  - `POST /revoke` (トークン失効)
- `response_type=code`, `scope=openid profile email` に対応する。

### 3.2 ユーザー管理
- ユーザーの登録（サインアップ）
- ID（メールアドレス）/ Password によるログイン
- パスワードのハッシュ化保存（bcrypt等）
- セッションCookieによるログイン状態保持

### 3.3 クライアント（RP）管理
- クライアントID・シークレットの発行
- 許可リダイレクトURIの登録
- スコープの設定

### 3.4 トークン仕様
- アクセストークン: JWT形式、有効期限15分
- IDトークン: JWT形式、署名アルゴリズム RS256
- リフレッシュトークン: ランダム文字列、有効期限7日

### 3.5 画面
- ログイン画面
- 同意画面（Consent Screen）
- 管理画面（任意：登録ユーザー・クライアント閲覧）

---

## 4. 非機能要件

### 4.1 セキュリティ
- PKCE（Proof Key for Code Exchange）のサポート
- HTTPS通信（開発環境では自己署名証明書可）
- パスワードストレッチング（bcrypt cost 10以上）
- XSS/CSRF対策（SameSite Cookie, CSP等）
- トークンの有効期限は短く設定する

### 4.2 性能
- トークン検証は署名検証によるステートレス化を基本とする
- データベースアクセスは必要最低限に抑える

### 4.3 可用性
- 個人開発/学習用途のため、単一プロセスでの動作を想定
- 永続化はRDBMSで行う

## 6. 開発フェーズ

1. **Phase 1**: データベース設計・ユーザー登録・ログイン機能
2. **Phase 2**: OAuth2/OIDC エンドポイント実装（Authorize, Token）
3. **Phase 3**: JWT発行・検証、UserInfoエンドポイント
4. **Phase 4**: デモ用RPアプリ作成（フロントエンド）
5. **Phase 5**: PKCE対応、セキュリティ強化

---

## 7. 制約・前提条件

- 本システムは学習目的であり、機密データの取り扱いは推奨しない。
- 実運用を行う場合は、追加のセキュリティ監査とMFA導入が必要。
