## モデルテストとは

モデルテストは、**Rails のモデル（データとビジネスルールを扱う層）が正しく動作するかを確認するテスト**です。

コントローラーやビューに比べて実行が速く、ビジネスロジックの正しさを直接検証できるため、テストの中心に据える価値があります。

---

## 主なテスト観点

### バリデーション

入力値がルールに沿っているかを確認します。

| 確認項目 | 例 |
| --- | --- |
| 必須項目 | `email`、`name` が空だと保存できない |
| 一意性 | 同じ `email` のユーザーは作れない |
| フォーマット | メールアドレスの形式、電話番号の形式 |
| 長さ | パスワードが 8 文字以上 |
| 数値範囲 | 年齢が 0 以上 150 以下 |
| 条件付きバリデーション | 特定の状態のときだけ必須になる項目 |
| カスタムバリデーション | 独自に定義した複雑なルール |

```ruby
it 'email が空だと無効' do
  user = build(:user, email: nil)
  expect(user).not_to be_valid
  expect(user.errors[:email]).to be_present
end
```

### 関連

モデル同士のつながりを確認します。

| 確認項目 | 例 |
| --- | --- |
| 関連の定義 | `belongs_to`、`has_many`、`has_one` が正しく機能する |
| 依存削除 | `dependent: :destroy` で子レコードも削除される |
| through 関連 | 中間テーブルを介した関連が取得できる |
| ポリモーフィック関連 | 複数のモデルに紐づく関連が機能する |

```ruby
it 'ユーザー削除時に関連する投稿も削除される' do
  user = create(:user)
  create(:post, user: user)
  expect { user.destroy }.to change(Post, :count).by(-1)
end
```

### スコープ・クラスメソッド

データの絞り込みや集計を確認します。

| 確認項目 | 例 |
| --- | --- |
| 絞り込み | `active` スコープで有効なレコードだけ取得できる |
| 並び順 | `order(created_at: :desc)` で新しい順になる |
| 集計 | `count`、`sum`、`average` の結果が正しい |
| 引数の組み合わせ | 条件を複数指定しても意図通り動く |

```ruby
it 'active スコープは有効なユーザーのみを返す' do
  active_user = create(:user, active: true)
  create(:user, active: false)
  expect(User.active).to eq([active_user])
end
```

### インスタンスメソッド

モデルに定義したビジネスロジックを確認します。

| 確認項目 | 例 |
| --- | --- |
| 戻り値 | 入力に対して正しい値を返す |
| 状態に応じた分岐 | 条件によって異なる結果になる |
| 副作用 | 他のレコードやファイルが変更される |

```ruby
it 'フルネームを返す' do
  user = build(:user, last_name: '山田', first_name: '太郎')
  expect(user.full_name).to eq('山田 太郎')
end
```

### コールバック

保存前後の自動処理を確認します。

| 確認項目 | 例 |
| --- | --- |
| 発火タイミング | `before_save`、`after_create` が適切なタイミングで動く |
| 正常系・異常系 | コールバック内でエラーが起きたときの挙動 |
| 条件付きコールバック | 特定の条件のときだけ実行される |

```ruby
it '保存前に email を小文字に変換する' do
  user = create(:user, email: 'TEST@EXAMPLE.COM')
  expect(user.reload.email).to eq('test@example.com')
end
```

### セキュリティ・機密情報

機密データの取り扱いを確認します。

| 確認項目 | 例 |
| --- | --- |
| ハッシュ化 | パスワードが平文で保存されていない |
| トークン | 認証トークンが生成され、有効期限が切れる |
| 暗号化 | 個人情報が暗号化・復号できる |

```ruby
it 'パスワードはハッシュ化されて保存される' do
  user = create(:user, password: 'password123')
  expect(user.password_digest).not_to eq('password123')
end
```

### データベース制約

マイグレーションで定義した制約と整合性を確認します。

| 確認項目 | 例 |
| --- | --- |
| NOT NULL | NULL を許可しないカラムに nil を入れると失敗する |
| UNIQUE | 一意制約違反が発生する |
| 外部キー | 存在しない親レコードを参照できない |
| CHECK 制約 | 範囲外の値を拒否する |

```ruby
it 'email に NULL を入れられない' do
  expect {
    User.create!(email: nil, password: 'password', name: 'Test')
  }.to raise_error(ActiveRecord::NotNullViolation)
end
```

### enum・定数

状態を表す値の管理を確認します。

| 確認項目 | 例 |
| --- | --- |
| 定義された値 | `enum` で定義した値が正しく機能する |
| スコープの生成 | `enum` から自動生成されたスコープが使える |
| 無効な値 | 定義外の値を拒否する |

```ruby
it 'role が admin のユーザーを絞り込める' do
  admin = create(:user, role: :admin)
  create(:user, role: :general)
  expect(User.admin).to eq([admin])
end
```

### ファクトリ

テストデータの生成が正しく行えることを確認します。

| 確認項目 | 例 |
| --- | --- |
| 基本の生成 | `create(:user)` で有効なレコードが作れる |
| トレイト | `build(:user, :admin)` などのバリエーションが正しく作れる |
| 無効なパターン | 必要に応じて無効なデータも作れる |

```ruby
it 'ファクトリが有効なユーザーを作る' do
  expect(build(:user)).to be_valid
end
```

### パフォーマンス

大量データや複雑なクエリを扱う場合に確認します。

| 確認項目 | 例 |
| --- | --- |
| N+1 問題 | `includes` などでクエリ数が増えない |
| 大量データ | ページネーションが正しく動く |

```ruby
it 'N+1 が発生しない' do
  create_list(:user, 10, :with_posts)
  expect {
    User.includes(:posts).map { |u| u.posts.size }
  }.not_to exceed_query_limit(1)
end
```

## よく使う RSpec の書き方

| 書き方 | 意味 |
| --- | --- |
| `expect(x).to be_valid` | `x` が有効であること |
| `expect(x).not_to be_valid` | `x` が無効であること |
| `expect(x).to be_present` | `x` が空でないこと |
| `expect(x).to eq(y)` | `x` が `y` と等しいこと |
| `expect(x).not_to eq(y)` | `x` が `y` と等しくないこと |
| `expect { ... }.to change(Model, :count).by(n)` | 処理でレコード数が `n` 件変わること |
| `expect { ... }.to raise_error(Error)` | 指定したエラーが発生すること |

## 確認チェックリスト

モデルテストを書く際は、以下を確認すると漏れが減ります。

- [ ] バリデーションルールが網羅されている
- [ ] 関連モデルの作成・削除の挙動を確認している
- [ ] スコープやクラスメソッドの結果が意図通りである
- [ ] インスタンスメソッドの戻り値と副作用を確認している
- [ ] コールバックの発火タイミングを確認している
- [ ] 機密情報が安全に扱われている
- [ ] データベース制約とモデルの整合性を確認している
- [ ] enum や定数の値が正しく扱われている
- [ ] ファクトリが正常に動作する
- [ ] 必要に応じてパフォーマンスを確認している
